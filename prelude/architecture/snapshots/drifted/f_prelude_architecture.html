Architecture

Change it with the agent

A Node server that serves Prelude’s pages, runs the agent one turn per design, and serves each design on an origin of its own, as that app’s server would. The desktop app is a window on it. Everything it produces is a file in the project’s folder.

Parts

Principles

  • The folder is the database. Everything Prelude produces is a file under prelude/, committed with the code. ~/.prelude holds only this machine’s conveniences, so nothing is lost if it goes.
  • The server is the one source of live state. Every window, the pop-out and a browser tab render from the server and follow it over its live channel, so none holds what another needs.
  • Code the agent wrote runs only in the sandbox. A design’s views are JavaScript written by the agent; rendering them in the server would undo the fences on what the agent may read and write.
  • Prelude knows no stack. A host renders the views; Prelude does everything else (routes, states, forms, the check), so every stack gets all of it.
  • Committed files merge cleanly. Several people work on one project on different branches: names never collide, transcripts only grow, and no index is rewritten by every session.
  • A design’s memory is its files. A design spans many sessions; each starts from the design’s files and notes, never from an earlier conversation.
  • Every native feature has a web fallback. The desktop app makes things nicer. It never makes them possible.
